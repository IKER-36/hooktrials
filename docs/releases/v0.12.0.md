# HookTrials v0.12.0 — safe validation and operational delivery

HookTrials `v0.12.0` closes the gap between configuring an integration and proving that it is ready
to operate. It adds explicit live-route validation, portable evidence, configurable incident
delivery and stronger demo isolation without changing the Product/Lab boundary.

## Included

- destination preflight checks network policy, DNS, TLS, HTTP reachability, contract readiness and
  signature configuration without sending a webhook payload;
- an explicit safe-test action creates a synthetic provider-shaped event, signs GitHub and Stripe
  starters when configured, and passes through the real ingestion and destination path;
- authenticated and public evidence can be downloaded as redacted JSON or Markdown from one
  server-side projection;
- alert channels support stable generic-webhook JSON or native Discord embeds, with independent
  Monitor/Webhook and opened/recovered scopes;
- Discord mention expansion is disabled, destination secrets remain encrypted and write-only, and
  changing provider cannot retain obsolete custom headers;
- empty, error and retry states across Product and Lab explain the next useful action instead of
  leaving blank surfaces or indefinite skeletons;
- Guided Demo setup, run cleanup and all-run reset are serialized per account with a token-safe,
  expiring Redis lock.

## Safety boundaries

Safe test events are synthetic but can reach the destination selected by the user. The interface
therefore keeps them explicit and recommends staging or an idempotent handler. Evidence exports and
alerts never include captured payloads, headers, credentials, signing secrets or destination URLs.
Demo cleanup continues to require the authenticated owner and exact private run identifier.

## Validation

- full formatting, ESLint, strict TypeScript, 150-test and production-build gate;
- real generic-webhook and Discord-shaped delivery against a local capture sink;
- functional authenticated/private and tokenized/public JSON/Markdown export checks;
- two concurrent demo setup requests proving one success, one conflict and one isolated run;
- cleanup and reset proving ordinary same-user resources remain untouched;
- English/Spanish, light/dark and browser-console review of changed product states.
