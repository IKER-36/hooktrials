# v0.19.0 — Reliability evidence and audit history

This release adds two practical views for teams operating integrations over time.

## New

- **SLO & reliability** turns monitor checks into an availability and latency view for 24-hour,
  7-day or 30-day windows.
- Each reliability window shows its target, check count, healthy outcomes, average latency, p95
  latency and incidents opened during the period.
- Every monitor receives the same measurements, so an operator can quickly find the dependency
  that is consuming reliability budget.
- **Audit history** records route, monitor, incident, recovery, alert and API-key actions in
  chronological order.
- Audit entries show the actor type, affected resource, result status and timestamp without copying
  payloads, credentials, destination URLs or authorization headers.
- CLI and scoped API-key actions appear in the same audit history as dashboard actions.

## Improvements

- Reliability views make the evidence window and sample size explicit instead of presenting an
  unexplained score.
- Empty states guide users to create a monitor or collect evidence before interpreting an SLO.
- Audit history is account-scoped and supports bounded filtering for safer hand-offs.

## Upgrade note

The release adds one additive database migration. Existing routes, monitor history, evidence and
API keys remain unchanged.
