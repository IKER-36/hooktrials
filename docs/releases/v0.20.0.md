# v0.20.0 — Shared workspaces and incident ownership

HookTrials now supports day-to-day collaboration without weakening the separation between accounts,
credentials and operational evidence.

## New

- **Team workspace** gives each account a clear shared operating space for routes, monitors,
  scenarios, status pages, incidents and audit history.
- **Workspace roles** provide owner, admin, operator and viewer access levels with predictable
  boundaries for configuration and recovery actions.
- **Invitations** create time-limited, single-use workspace access tokens and show pending invites
  to administrators.
- **Incident assignees** make ownership visible in Operations. An incident can be assigned to any
  current workspace member, reassigned or left unassigned.
- Existing accounts are migrated into a workspace automatically, so their routes and evidence stay
  available after updating.

## Improved

- Dashboard resource lists and operational views now include the active workspace instead of being
  limited to the account that created a resource.
- Viewers remain safely read-only, while operators retain the actions required to acknowledge,
  assign and recover operational work.
- Workspace mutations and incident triage continue to appear in the redacted audit history.
- Team workspace copy and invitation tokens never include payloads, destination URLs or secrets.

## Upgrade note

The release adds additive migrations for workspaces, memberships, invitations and incident
assignment. Existing resources are linked to a new personal workspace automatically. No route,
monitor, API key or evidence link needs to be recreated.
