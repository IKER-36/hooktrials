# v0.27.0 — Safer self-hosted updates

Self-hosted operators now have a clearer, recoverable workflow for updating HookTrials without
losing users, endpoints, events or runtime secrets.

## Added

- Preview a tagged update with `./hooktrials update --release vX.Y.Z --check`.
- Create protected database and runtime-configuration snapshots before updating.
- Inspect the last update state from `./hooktrials status`.
- Restore the previous application checkout with `./hooktrials rollback --yes`.

## Improved

- Failed builds restore the previous checkout automatically and keep the backup paths visible.
- The update output now separates the database backup, runtime backup and rollback command.
- The documentation clarifies that application rollback does not delete or rewrite PostgreSQL and
  Redis data.

## Fixed

- A failed release switch is recorded as failed instead of leaving an ambiguous update state.
- Rollback requires an explicit confirmation flag to prevent accidental downtime.
- Database migrations are never reversed silently; the operator always receives a recovery backup
  reference.

No application data migration is included.
