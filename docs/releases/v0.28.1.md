# v0.28.1 — Safer alert and status-page workflows

This maintenance release makes two operational workflows easier to complete safely: configuring
what is shared on a public status page and cleaning up an alert destination when it is no longer
needed.

## Added

- A live **Public preview** appears while creating or editing a status page, showing selected
  monitors, their current health and the redacted information that can be shared.
- Alert channels can be removed from **Operations** when a Discord or generic webhook destination
  is no longer needed.
- Status-page actions use the same accessible confirmation dialog as the rest of the dashboard.

## Improved

- The status-page preview updates as the headline, description, accent and monitor selection change,
  so the public result is clear before it is published.
- Rotating a public link explains that the previous URL will stop working before the action runs.
- Removing an alert channel stops future notifications while keeping historical delivery evidence in
  Operations.

## Fixed

- Replaced browser-native delete and rotate prompts with keyboard-friendly, focus-trapped dialogs.
- Added a clear cleanup path for saved alert destinations.
- Kept public status pages limited to selected monitor names, redacted hosts and health metrics.

No API, database or account migration is required.
