# v0.30.0 — OpenAPI import for monitored integrations

HookTrials can now turn an existing OpenAPI contract into a reviewed set of monitors. This keeps
the first monitoring setup quick while preserving the same explicit safety boundaries used by the
rest of the product.

## Added

- **OpenAPI import** is available from **Resources → Import OpenAPI** and from the Monitoring and
  Documentation pages.
- Import a JSON or YAML OpenAPI 3.0/3.1 document by uploading a file, pasting its contents or
  loading a public URL that allows browser access.
- Review the detected server, operation names, paths, methods and expected successful status
  ranges before creating anything.
- Create up to 20 monitors in one reviewed action, with separate results for successful and failed
  creations.
- Generated monitors support the existing Test and Staging environments and can be edited from
  Monitoring immediately after import.

## Safety and behavior

- The contract is parsed in the browser; it is not proxied through HookTrials.
- Authentication schemes, security headers, request bodies, examples and secrets are never copied.
- Paths with unresolved parameters are displayed but skipped until concrete values are available.
- GET and HEAD operations are selected by default. POST operations require an explicit opt-in and
  are labelled because an empty request can still have side effects.
- Unsupported write methods remain visible with an explanation instead of silently being ignored.
- Production is intentionally excluded from the import action so every generated monitor can be
  reviewed first.

## Improved

- The OpenAPI catalogue and the importer now form one workflow: discover the contract, review safe
  operations and then observe the resulting service health in Monitoring.
- Documentation now explains the browser-only parsing model, limits and recommended workflow in
  both the public guide and the in-product entry points.
- The new surface follows the shared workspace hierarchy, dark/light semantic tokens, keyboard
  focus rules and mobile layout used by the rest of the dashboard.

## Compatibility

This release adds a dashboard workflow and documentation only. Existing accounts, routes,
monitors, events, API keys and stored evidence remain compatible. No database migration is needed.
