# v0.31.0 — Delivery policies for resilient routes

HookTrials Protect routes can now describe what should happen when one backend is slow, unavailable
or needs to receive the same event alongside another system. The new controls make delivery intent
visible without changing the existing Trial and Observe workflows.

## Added

- **Single destination** remains the default and continues to use the configured retry policy.
- **Fan-out** sends each event to up to three active targets and tracks the result for every target
  separately.
- **Failover** follows an ordered primary-to-fallback chain after the current target exhausts its
  retry budget.
- **Idempotency scope** can be set per destination or per event. Protect deliveries include a
  stable `X-HookTrials-Idempotency-Key` header across retries.
- Webhook Hub and route configuration now show the current topology, redacted target hosts and a
  write-only editor for replacing delivery targets.
- The API contract documents the delivery policy shape without returning URLs, headers or secrets.
- New public guidance explains the topology choices, safe setup flow and evidence model.

## Improved

- Fan-out delivery records preserve an independent retry timeline for each target.
- Failover hand-offs remain visible in Operations and keep the failed primary evidence available for
  review or replay.
- Existing routes continue to use their legacy single-destination configuration automatically.
- The policy controls use the shared compact layout and remain usable on narrow screens.

## Fixed

- Protected routes no longer need separate application logic to attach a deduplication key to each
  retry.
- Updating an existing advanced route without changing its topology no longer asks for write-only
  destination values again.
- Destination URLs and custom headers stay encrypted and are never returned in endpoint listings or
  API responses.

## Compatibility

This release adds an additive database migration. Existing accounts, routes, events, monitors,
evidence and API keys remain compatible. Trial and Observe routes keep their current behavior.
