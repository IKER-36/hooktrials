# v0.32.0 — SLOs and error-budget alerts

Released 1 August 2026.

## New

- Set an availability objective and rolling window on every monitor.
- Track remaining error budget, budget consumption and burn rate for each monitor.
- See objective status directly in the reliability workspace: collecting evidence, healthy, at risk or breached.
- Receive the same Discord or HTTPS alert notifications when a monitor exhausts its reliability budget.
- Reliability incidents include the target, window, check count and failed outcomes so the alert can be acted on immediately.

## Improved

- Existing monitors keep their current targets and checks while receiving a sensible default objective during upgrade.
- Reliability summaries now use each monitor's configured objective instead of applying one hidden target to every resource.
- The monitoring editor explains how many checks are needed before an SLO alert can open.

## Fixed

- Prevented a budget alert from replacing the normal availability incident for the same monitor.
- Recovery notifications now close the SLO incident independently when the rolling window is healthy again.

See [SLOs, error budgets and alerts](../slo-and-alerts.md) for the complete end-user guide.
