# HookTrials v0.35.0

## Integration Activation & Reliability Cockpit

This release makes the first live integration easier to configure, test and understand. Instead of
jumping between the Webhook Hub, the delivery timeline and Operations, each live route now has one
focused place to see what is configured and what has actually happened.

### Added

- A dedicated **Integration cockpit** for every live Observe or Protect route.
- A clear provider → HookTrials → backend flow with the active environment, delivery mode and
  route state visible at a glance.
- A single-click safe test event from the cockpit, with the result added to the same evidence
  timeline as real traffic.
- A compact readiness summary showing which reliability controls are already proven and which need
  attention.
- Recent event history with correlated attempts, delivery outcomes and direct access to the full
  event inspector.
- Recovery context for related incidents and dead letters, including direct access to Operations.
- Provider setup kits for Generic webhook, Stripe, GitHub, Shopify, Slack, GitLab, Linear and
  HubSpot.
- Copy-ready synthetic `curl` examples and a concise list of headers to expect for each provider.

### Improved

- **Build → Integrations** now leads live routes to their own cockpit; Test Lab routes continue to
  use the Delivery timeline.
- The provider configuration form explains the next setup step without hiding the existing
  preflight, signature and delivery-policy controls.
- Public ingestion URLs can be copied from both the creation flow and the integration cockpit.
- Mobile layouts collapse the traffic flow and evidence rows without removing the primary actions.
- Provider kits explicitly recommend synthetic payloads and keep credentials write-only.

### Fixed

- Live integrations no longer appear to be owned only by the generic Control Center route.
- The path from creating a route to sending the first verified event is now explicit and reversible.
- Recovery evidence is shown in the context of the integration that needs attention.

No database migration is required. Existing accounts, routes, monitors, events and credentials are
preserved.
